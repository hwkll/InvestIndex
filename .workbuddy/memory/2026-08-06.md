## InvestHub 实现（PRD v1.1 落地）

根据分享的 PRD（个人综合投资管理平台 InvestHub）从零实现了一个可运行的全栈应用。

**关键决策**：PRD 规划 Go + Vue3 + ECharts，但本环境无外网（go mod / CDN 均不可用），故改为
**零依赖 Node.js + 原生前端**实现，严格遵循 PRD 的架构 / API 契约 / DDL / 功能清单：
- 后端 Node 22 内置 `node:sqlite`（启动需 `--experimental-sqlite`），标准库 http 实现 REST + SSE。
- 前端原生 HTML/CSS/JS 单页应用，图表全部自绘 SVG，无构建步骤、无 CDN。

- AI：配置 DeepSeek Key 时真实调用；未配置时用本地启发式分析，同样输出结构化 JSON。

**文件结构**：`server/{server,db,core,quotes,indicators,ai,alerts,settings,crypto}.js` + `web/{index.html,styles.css,app.js}` + `README.md`。

**已验证**：资产/流水/持仓引擎（移动加权平均）、收益分层聚合、现金账户纳入总资产、仪表盘汇总、指标(MA/MACD/RSI/KDJ/BOLL)、K线、AI 双模式分析+历史、提醒引擎、SSE 实时推送（30s 轮询）、访问口令(scrypt)、AES-256-GCM 加密 Key、JSON/CSV 备份导入导出、首次启动演示数据种子。

## 16:20 代码审查（审查当前项目是否有bug）

以「高级开发工程师」身份对 6 模块落地代码做审查，发现并修复 2 个真实 bug：

**Bug A（HIGH，已修复）— 基准对比(Later-②) 时间轴倒置 + 超额收益算反**
- 根因：`core.go` `PnlTrend()` 调 `quotes.Kline(id,"1d",n)`，而 `Kline` 返回 `ORDER BY ts DESC`（最新在前）。代码把 `kl[len(kl)-n:]`（最旧 n 根）当窗口起点、与 `series`（ASC，最旧在前）按索引对齐 → 最新收盘价被错配到最旧日期，基准折线整体反向；同时 `excessReturn` 用 `klTail[n-1]`（最旧收盘）算收益，符号也反。
- 现象（实测）：设 benchmark=BTC、range=7d，折现为 `100→…→190.74` 乱序，excessReturn=-1.138（明显错）。
- 修复：在 PnlTrend 内把 `raw` 反转为 ASC 再对齐。重测：`100→51.2→…→52.5`（BTC 窗口内约 -47%），excessReturn=+0.2474（组合 -22.76% 跑赢基准约 +24.7pp），方向正确。
- 残留边角：当标的 K 线数量 < 所选区间天数（如区间内新建标的）时仍按索引对齐，可能轻微错位（非崩溃，常见场景已正确）。如需 100% 严谨可改为按日期 join，列入后续优化。

**Bug B（MEDIUM，已修复）— Dashboard「今日最强/最弱」列恒为 `--`**
- 根因：`DashboardView.catRows` 读 `pc.subtotal?.top`，但 `PositionsByCategory` 的 `Subtotal` 结构体**不含 top**（只有 currency/mv/cost/fl/realized/floatingPct），top movers 仅在 `GlobalSummary` 的 `CategorySummary.Top` 里算。posCache 始终有值→恒走实时分支→该列永远 `--`。顺带 realizedPnl 被硬编码 0。
- 修复：该列改读 `summary.value.categories[c].top`（每 30s 刷新，已正确算出）；realizedPnl 改读 `pc.subtotal.realizedPnl`。

**收窄/排除的误报**
- `Api.positions(c)` 调 `GET /positions?category=crypto`（query 参数），后端 `handlePositions` 支持 → Next-⑥ 实时增量合并**实际可用**，非 bug（之前的 404 是我 curl 用了 path 形式 `/positions/crypto` 误判）。
- `webhook-test`（无 URL）返回 envelope `code=0 msg=ok` 但 `data.ok=false`+错误文案 → 逻辑正确，非 bug（我初看只打了 envelope 字段误以为 ok）。
- SSE `quote` 事件 payload 含 `assetId`，与 `store.quotes[q.assetId]` / `app.live(row.assetId)` 一致 → 实时合并链路正确。
- 单标的分类 topMovers 把同一标的同时当 up & down（如 fund/gold/stock 各仅 1 标的）→ 纯展示瑕疵，低优先级，未动。

**构建/验证**：两处修复后 `npm run build`(dangerouslyDisableSandbox) + `go build -o investhub` + `go vet ./...` 全绿；重启服务：基准顺序正确、summary/positions/assets/watchlist/alerts/fx/pnl-trend 7 个端点均 200；webhook-test 无 URL/不可达 URL 均正确返回 ok:false+中文错误；测试残留（benchmark/webhook_url）已 `PUT /settings` 清空。

### 设计决策
- **骨架屏替代 loading 文字**：StatCard 在数据加载期间显示与真实卡片同尺寸的脉冲灰色块，消除布局跳动（CLS），用户感知更流畅。
- **confirm() → ModalDialog**：原生 `confirm()` 不可定制样式且阻塞 UI，全局 ModalDialog 方案统一了视觉风格（品牌色按钮、danger 红色、标题/详情两段式）。
- **Transition mode="out-in"**：先淡出旧页面再淡入新页面，避免页面短暂重叠。
- **EChart 空状态**：用绝对定位的居中提示层覆盖隐藏的 ECharts canvas，切换通过 `v-if` 控制，避免 canvas 残留。

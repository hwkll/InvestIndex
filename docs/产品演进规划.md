## 0. 方法论与重要声明

本文基于对代码库的系统走查完成：`internal/`（全部包：core / quotes / ai / alerts / indicators / settings / store / api）+ `frontend/`（全部视图与核心 JS）。结论分为两级：

- **【已验证事实】**：可在代码中找到直接证据（文件路径 + 行为），属于确定的能力边界或缺陷。
- **【待验证假设】**：项目**当前没有任何真实用户反馈或使用数据埋点**（无 analytics、无 NPS、无行为日志）。凡涉及"用户想要/用户痛点"的论断，均为基于功能形态的合理推测，必须靠用户研究确认，不得当作既定事实。

## 1. 核心功能模块梳理

| 模块 | 能力 | 真实边界（代码证据） | 状态 |
|------|------|----------------------|------|
| 持仓引擎 `core` | 资产/持仓/盈亏/汇总/趋势 | 移动加权平均成本法；4 类资产（crypto/fund/gold/stock）；日盈亏用 PrevClose | 核心可用 |
| 行情 `quotes` | 行情获取 + K线 | auto/real/sim 三模式；CoinGecko（**仅硬编码 12 币种映射**）+ 新浪；失败降级确定性随机游走 | 部分受限 |
| AI 分析 `ai` | 标的/组合分析 | DeepSeek（可配 key）优先，失败降级本地启发式（RSI/MACD/KDJ/MA 打分）；限流 2 并发 | 可用但有依赖 |
| 提醒 `alerts` | 规则引擎 | 5 类规则（price/percent/range_break/ai_signal/schedule）；debounce 5min；**邮件通道为 `sendMailStub` 占位** | 部分实现 |
| 技术指标 `indicators` | 指标计算 | SMA/EMA/MACD/RSI/KDJ/Boll/夏普/回撤等纯函数，质量高 | 成熟 |
| 实时推送 `sse` | 行情/提醒/AI 广播 | EventSource hub；25s ping 保活；慢客户端非阻塞丢帧 | 可用 |
| 调度 `scheduler` | 轮询与快照 | 30s 轮询（可配）；每日 23:55 快照；启动 SeedDemo + 90 天历史 | 可用 |
| 认证 `api/auth` | PIN + 会话 | 设 PIN 后 HttpOnly cookie（30 天滑动）；5 次失败锁 5 分钟 | 可用 |
| 数据备份 `backup` | 导出导入 | JSON 全量（10 表）；CSV 仅导出/导入**交易流水** | 可用但偏窄 |
| 现金账户 `cash` | 多账户现金 | 银行卡/券商账户；合计计入总资产 | 可用 |
| 前端 `frontend` | 7 个视图 | 仪表盘/持仓/交易/AI/提醒/现金/设置；Pinia + ECharts | 可用，桌面为主 |

**能力全景一句话**：一个"本地优先、零配置、单二进制"的个人投资账本+行情+AI 分析工具，核心价值闭环（记账 → 看板 → 分析 → 提醒）已打通，但**数据真实性治理、提醒触达、性能弹性**三处明显偏薄。

## 2. 现有用户流程还原

### 2.1 首次接入流程
1. 启动二进制（或 `go build` 后运行）→ 自动创建 `data/` + `master.key` + 播种演示数据（5 标的 / 5 交易 / 2 现金账户 / 90 天合成历史）。
2. 浏览器打开 `:7788` → 无 PIN 则直接进仪表盘；设 PIN 后需登录。
3. 看到的是**演示数据**，需手动在「持仓」里新增自己的标的 + 记交易。

> **交互成本**：零安装成本（单二进制），但**首次使用没有引导**——用户面对一堆别人的演示数据，不知道"该删掉演示、建自己的"。空状态与引导缺失是首屏最大摩擦。

### 2.2 日常看板流程
1. 打开仪表盘 → 4 张 StatCard（总资产/今日盈亏/成本/持仓数）+ 资产分布 donut + 资产趋势折线（7d/30d/90d/all）+ 分类概览表。
2. SSE 推送实时价 → 前端 4s 防抖后**全量 reloadSummary**。
3. 点击分类/标的 → 进入持仓 / 标的大详情（K线 + 指标 + AI 结论）。

> **交互成本**：信息密度高、一屏看清。但趋势折线初始是**合成数据**（见 §4.1-3），用户前 90 天看到的是假的走势。

### 2.3 记账流程
1. 「持仓」→ 选分类 tab → 新增标的（填 symbol/名称/分类/币种）。
2. 「交易流水」→ 记一笔（buy/sell，金额/数量/手续费/日期）。
3. 系统用移动加权平均重算持仓成本与盈亏。

> **交互成本**：单笔录入顺畅。但**批量/CSV 导入只认交易流水**，且按 symbol/name 匹配已有标的——导入前必须先把标的建好，否则匹配失败。无"从券商导出的完整对账单一键导入"。

### 2.4 分析决策流程
1. 「AI 分析」→ 选某标的或"整体组合" → 触发 `Analyze()`（DeepSeek 或启发式）。
2. 查看 signal / confidence / 文字结论；历史分析可分页回看。
3. 设提醒规则（价格/百分比/破位/AI 信号）→ 触发时**仅应用内角标 + 占位邮件**。

> **交互成本**：分析链路清晰。但**提醒无法真正触达用户**（邮件是 stub），用户必须主动打开应用才知道触发——实时价值的最后一环断了。

## 3. 体验现状（交互 / 性能 / 易用性）

### 3.1 交互设计
- ✅ 侧边栏导航 + 版本/连接状态指示灯，信息架构清晰。
- ✅ 实时指示灯 + 提醒角标，状态可见性好。
- ⚠️ **无新手引导 / 空状态**：首次面对演示数据无"从零开始"入口。
- ⚠️ **趋势图默认展示合成历史**，未明确标注"演示数据"，易让用户误判为真实走势。
- ⚠️ 提醒视图里"邮件通道"标注了占位，但设置里仍可能让人以为已连通。

### 3.2 性能表现
- ⚠️ **实时刷新 → 全量重算**（§4.1-5）：SSE 每个 quote tick 触发 4s 防抖的 `reloadSummary()`，每次重算所有持仓/汇总。标的数量大（数十~上百）时 CPU 与 DB 压力显著。
- ⚠️ **单写连接瓶颈**（§4.1-7）：`db.SetMaxOpenConns(1)` 串行化；AI 分析阻塞 60–120s 期间，行情轮询与 UI 查询排队，可能出现卡顿。
- ✅ SQLite WAL + 单连接一致性好，小数据量下体感流畅。
- ⚠️ 历史快照为随机数（§4.1-3），PnlTrend 聚合在真实数据缺失时给出"看起来合理但假的"曲线。

### 3.3 易用性
- ✅ 单二进制、零配置、本地隐私优先——部署与信任成本低，是核心卖点。
- ⚠️ **行情源透明度不足**（§4.1-4）：未映射的 crypto 静默降级为 sim，用户可能以为在看真实价格；real 模式下 CoinGecko 仅 12 币种。
- ⚠️ **跨币种聚合口径隐患**（§4.1-2）：`core.aggregate()` 跨币种 bucket 货币取 `items[0].Currency`，混合币种时汇总货币可能错。
- ⚠️ **CORS 配置矛盾**（§4.1-1）：`Allow-Origin: *` 与 `Allow-Credentials: true` 同设，浏览器实际会拒绝；本项目同源部署故影响有限，但反代/跨域场景会踩坑。

## 4. 功能缺口与体验痛点

### 4.1 已验证事实（代码层证据）

| # | 痛点 | 证据位置 | 影响 |
|---|------|----------|------|
| 1 | CORS `Allow-Origin:*` + `Allow-Credentials:true` 同设，浏览器会拒绝 | `internal/api/api.go` 路由配置 | 反代/跨域部署失败 |
| 2 | 跨币种聚合货币取 `items[0].Currency` | `internal/core/core.go` `aggregate()` | 混合币种汇总口径可能错误 |
| 3 | 历史快照为随机数合成 | `internal/core/core.go` `SeedHistoricalSnapshots` | 趋势图初始非真实数据 |
| 4 | CoinGecko 仅硬编码 12 币种映射，未映射 crypto 静默降级 sim | `internal/quotes/quotes.go` | 用户可能误以为看真实行情 |
| 5 | SSE quote tick → 4s 防抖全量 `reloadSummary` | `frontend/src/views/DashboardView.vue` watch | 标的数量大时性能开销显著 |
| 6 | 邮件提醒为 `sendMailStub` 占位，未实现真实 SMTP | `internal/alerts/alerts.go`（注释标 P1） | 提醒无法真正触达 |
| 7 | `db.SetMaxOpenConns(1)` 单写连接，AI 阻塞 60–120s 串行 | `internal/store/store.go` | UI 请求在 AI 分析期排队 |
| 8 | CSV 导入仅支持交易流水，需先建标的 | `internal/api/backup.go` | 批量导入摩擦大 |

### 4.2 待验证假设（需用户研究确认）

> 以下为基于功能形态的推测，**不是已观测事实**，需通过访谈/问卷/埋点验证。

- H1：用户希望**真实触达提醒**（邮件/推送/IM），当前 stub 是最大弃用风险点。
- H2：用户存在**跨市场多币种持仓**（A股/美股/港股/加密），当前币种与汇率处理偏薄弱。
- H3：用户想要**非持仓的"关注/自选"**跟踪（只看不买），当前只能跟踪已持仓。
- H4：用户需要**目标配置与再平衡**建议，而非仅被动展示盈亏。
- H5：用户希望**移动端可看**（手机查看仪表盘），当前 UI 偏桌面。
- H6：新手在"演示数据 vs 自己的数据"之间存在认知困惑，需要引导。
- H7：用户期望**税务/多种成本计量**（FIFO 等），当前仅移动加权平均。

### 4.3 痛点优先级矩阵（Impact × Effort，定性）

| 痛点 | 影响 | 修复成本 | 排序 |
|------|------|----------|------|
| 提醒触达（#6） | 高（断闭环） | 中 | 🔴 高优先 |
| 实时性能（#5,#7） | 高（规模化必爆） | 中 | 🔴 高优先 |
| 演示数据误导（#3,#4） | 中高（信任） | 低 | 🔴 高优先 |
| 引导/空状态（H6） | 中（首屏留存） | 低 | 🟠 中优先 |
| 跨币种口径（#2,#8↔H2） | 中 | 中 | 🟠 中优先 |
| 关注列表（H3） | 中 | 中 | 🟡 中低 |
| 多端/暗色（H5） | 中 | 中 | 🟡 中低 |

## 5. 未来演进方向（总览）

1. **把"实时闭环"做真**：真实多渠道提醒 + 增量刷新 + 单连接瓶颈解除。
2. **把"数据信任"做硬**：行情源透明标注、历史数据真实回填/明确演示标识、跨币种正确聚合。
3. **把"分析深度"做厚**：关注列表、目标配置与再平衡、基准对比与收益归因、AI 叙事周报。
4. **把"易用性"做顺**：新手引导、移动端/暗色、导出增强、通知中心。
5. **把"决策辅助"做准**：更稳的 AI（多模型 + 回测校验）、可解释的成本与税务计量。

## 6. 新功能规划 + RICE 优先级

> RICE = (Reach × Impact × Confidence) ÷ Effort
> - Reach：覆盖场景广度（1–10，估计值，非真实埋点）
> - Impact：0.25 / 0.5 / 1 / 1.5 / 2 / 3
> - Confidence：0.5 / 0.7 / 0.8 / 0.9 / 1.0
> - Effort：人周（开发+测试）
> 所有 Reach/Impact 均为**估计**，须在用户研究后校准。

## 7. Now / Next / Later 三阶段路径

### 🟢 Now（v1.2，0–3 个月）— "把闭环做真、把信任做硬"
**目标**：消除最高危的断点与误导，奠定可规模化基础。
- F11 新手引导 + 空状态（低成本高杠杆，先上）
- F4 实时刷新性能优化（增量更新，解除 #5/#7 瓶颈）
- F1（第一批）真实 SMTP 邮件提醒（兑现 P1，先打通邮件）
- F3 演示数据清晰标注 + 历史真实回填入口
- F2（第一批）行情映射透明度：未映射 crypto 明确标注"模拟"，避免误导
- 顺带修 #1 CORS 配置、#2 跨币种聚合口径

**里程碑**：演示数据不再误导；提醒能真正发邮件；50+ 标的下看板不卡。

### 🟡 Next（v1.3，3–6 个月）— "把覆盖做广、把分析做厚"
- F2（完整）行情源大幅扩展（更多 crypto/fund/美股/港股映射）
- F5 多币种与汇率处理（FX 表 + 正确聚合）
- F6 关注列表 / 自选
- F15 AI 叙事周报
- F1（第二批）Webhook / Telegram / 浏览器推送

**里程碑**：跨市场多币种可用；非持仓也能跟踪；每周自动出 AI 总结。

### 🔵 Later（v2.0，6–12 个月）— "把决策做准、把体验做顺"
- F7 目标配置 & 再平衡建议
- F8 基准对比 & 收益归因
- F9 暗色模式 & 移动端响应式
- F10 成本计量方法扩展（FIFO 等）
- F12 导出增强 / F13 通知中心 / F14 只读分享（按需求验证再定）

**里程碑**：从"记录工具"升级为"决策辅助"；手机可看；可解释的成本与税务。

## 8. 指标体系（北极星 + 驱动 + 健康）

> 当前无埋点，以下为**建议接入的指标体系**，需在 Now 阶段嵌入事件采集。

**北极星指标**：周活跃持仓用户数（WAU with ≥1 持仓且 ≥1 次看板查看）——衡量"真实在用"。

**驱动指标（按阶段）**：
- Now：提醒触达成功率（真实发送/触发）、实时刷新 P95 延迟、演示数据误读率（引导后留存）
- Next：跨币种持仓覆盖率、关注列表添加率、AI 周报打开率
- Later：再平衡建议采纳率、移动端日活占比、导出/分享使用率

**健康指标（技术）**：
- 行情轮询成功率（real 模式）、AI 分析 P95 耗时、DB 写阻塞等待时长、SSE 断连率

**基线建议**：Now 阶段先建立埋点 + 上述指标基线，Next/Later 用数据校准 RICE 中的 Reach/Impact 估计值。

## 9. 风险与依赖

| 风险 | 说明 | 缓解 |
|------|------|------|
| 数据真实性信任危机 | 合成历史 + sim 静默降级，用户误判 | F3/F2 标注 + 真实回填；诚实展示数据来源 |
| 规模化性能 | 单连接 + 全量重算，标的数大时崩 | F4 增量刷新 + 连接池/读写分离评估 |
| 外部依赖不稳 | CoinGecko/新浪限流或变更 | 多源 + 优雅降级 + 明确状态标识 |
| AI 成本与不确定性 | DeepSeek 计费/超时 | 限流 + 启发式兜底 + 结果可解释 |
| 无用户验证 | 全部 RICE 为估计 | 嵌入埋点 + 用户访谈（见 §10），下个季度重算 RICE |
